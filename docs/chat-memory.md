# 1対1チャットの長期記憶

2026-09-27。既存の RoleplayChatService / RoleplayRepository / RoleplayPromptBuilder を拡張。新しい外部サービス・検索基盤は追加していない。

## 5種類の情報

| 情報 | 保存・入力 |
| --- | --- |
| Character Profile | 既存の Oshi と追加の RoleplayProfile。抽出処理から書き込まない。無料・お試し・プレミアムの利用条件を維持。 |
| User Profile | 既存の memories に kind=profile を追加。実生活/ロールプレイの領域別、項目別の現在値。返答では user_profile ブロックへ分離。 |
| Relationship State | 既存の relationship、relationshipEvents、unlocks、specialNickname を利用。進行条件、反復対策、日次・時間上限は変更しない。 |
| Important Memories | kind=event。past / planned / ongoing / cancelled / resolved を区別。元発言ID、観測日時、明示された予定日、関連プロフィール項目を保持。 |
| Recent Conversation | 無料20件/プレミアム40件を維持し、さらに本文合計12,000/24,000文字に制限。既存要約を補助利用。今回の入力は最大12,000文字。 |

ユーザープロフィールの項目は name / birthday / job / hobbies / likes / dislikes / favorite_animal / food_dislikes / location。複数の趣味や苦手な食べ物は、引き続き有効な項目を統合するよう抽出に指示する。ユーザーの明示的な発言IDが必要で、AI側の発言、explicit=false、領域不明の情報は確定プロフィールとして受け入れない。一時的な気分・推測・質問・仮定をプロフィールへ入れないよう抽出に指示する。

すべて `roleplay/{userId}/{oshiId}` に保存。ユーザー間・キャラクター間の共有は追加していない。読み書きと非同期の返信完了時にも認証ユーザーを照合する。

## 検索と更新

- 今回の発言と直近8件（両話者）の会話を検索クエリに使う。指示語の参照先を含められる。
- プロフィール用の枠を確保し、残りで関連する出来事を選ぶ。合計は既存の無料12件/プレミアム24件の範囲内。
- 既存の日本語bigram/英単語検索に、抽出AIが作る意味タグ・言い換えと、端末内の概念辞書を組み合わせる。誕生日/生年月日、約束/お出かけ、猫/犬/ペットなどを同じ概念として照合。専用の埋め込みAPIやベクトルDBは利用していない。
- 同じプロフィール項目や同じ出来事の現在値は置換。correction は旧値を破棄し、change は直前の値を履歴データとして1件だけ残す。旧値は現在値として返信入力へ渡さない。
- 明示的な訂正/変化の分類がない矛盾は保存を中断する。古い未処理会話が現在の事実を上書きしないよう観測日時も確認する。
- キャラクター設定・関係性が記憶で変更される経路は追加していない。記憶・要約はデータとして囲み、区切りタグを無害化。証拠がない情報はキャラクターの口調で確認するよう返答生成に指示する。

## 抽出と永続化

古い未処理分から、1回最大40発言・本文16,000文字で抽出。長い単一発言は断片に分け、同じ元発言IDと永続化した文字位置から続きを処理する。1返信あたり抽出/再試行は最大4回。失敗時には最古のバッチを小さくして再試行し、残りは次の返信で継続する。

記憶・要約・取り込み時刻・同時刻の処理済み発言ID・長文の読み取り位置・memoryRevision をFirebaseトランザクションで一括保存する。読み込んだ位置/版が変わっていた場合は中断する。安定した記録IDと項目/出来事の更新により再処理の重複を抑える。無効なJSONや元発言IDの不一致でも位置を進めない。

関係性の更新は記憶の保存成功後だけ行う。長文の断片ごとにユーザーの会話回数を増やさない。保存後・関係性更新前にアプリが終了した場合、そのバッチの関係性変化が適用されない可能性は残る（記憶保存との別トランザクションは既存の構成を維持）。

## 互換性と削除

既存の記録には kind=legacy / domain=unknown を補い、そのまま読み込む。過去に保存されていない元発言IDや領域を捏造しない。新しいユーザー発言に根拠があれば、既存記録IDを参照して構造化した記録へ更新できる。保存上限は無料150件/プレミアム500件を維持する。

削除は記録だけでなく、同じ根拠発言を持つ記録、同じ項目の記録、関連プロフィール項目・概念で特定できる派生の思い出も対象にする。要約は選択的に安全な削除ができないため全体をクリアし、削除前の履歴をAIへの入力と再抽出から外す。古い履歴から作る補助メモも無効化する。画面上のチャット履歴自体は削除しない。削除失敗時は一覧を再取得してエラーを表示する。

削除により関係する思い出や直前の会話文脈も失われる場合がある。旧記録に由来情報がない場合、別の旧記録との意味的な依存関係を完全には特定できない。

## 費用と速度

通常の返信は既存と同じモデル・1回の生成。記憶検索は端末内で行い、追加の検索API料金はない。抽出は返信後の非同期処理なので、返信前に抽出を待つ構成にはしていない。

構造化された情報により入力・抽出の出力量は増える。抽出の出力上限は800から2,400トークンへ変更した。バックログ時は最大4回の抽出/再試行が発生するため、以前よりAPI費用とFirebase転送量が増える。通常返信の400トークン（長文設定900）、サーバーの省略時既定1,000トークン、日次呼び出し上限は維持。実際の料金・応答時間・転送量は未計測。

`functions/index.js` も出力の許可上限を2,400へ変更した。**本番へのデプロイは未実施**。新しいアプリを本番に反映する前に、既存の aiChat 関数の更新が必要。許可上限が1,000のままでは抽出JSONが途中で切れる可能性がある。

Realtime Databaseの本番ルールも、このユーザー自身の `roleplay/{uid}/{oshiId}` へのルート単位のトランザクションを許可している必要がある。リポジトリには該当する現行ルール全体がないため、実際の権限と複数端末での競合は未検証。

意味検索はタグ・辞書を使う方式なので、任意の言い換えへの完全な対応を保証するものではない。領域判定と抽出内容の意味的正しさは引き続きLLMに依存する。1返信で処理しきれないバックログは次の会話で継続する。以前の実装ですでに取り込み位置より前に飛ばされた会話は、自動的に位置を戻さないため、この更新だけでは復旧しない。
